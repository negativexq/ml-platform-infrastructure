# M13 Gate — Platform Domain Foundation

Run date: 2026-10-02. First milestone of the control-plane platform
([plan](../../history/platform-milestones.md)). Nothing here runs MLflow, Argo or
Kubernetes: this milestone is the domain, its persistence, and the rules that
keep it independent of every subsystem it will later adapt.

## What was built

`controlplane/` — `domain` (12 core entities, 7 state machines), `application`
(provider ports, unit of work, `ProjectService`), `persistence` (SQLAlchemy +
Alembic, plus an in-memory unit of work), `api` (FastAPI), `adapters` (in-memory
fakes for all five provider ports; real adapters arrive in later milestones).

## Gate checklist

| Gate | Proof |
| --- | --- |
| PostgreSQL migrations apply to a clean database | `test_migrations_apply_to_a_clean_database` — schema dropped and recreated per test, real PostgreSQL 16 |
| Every core entity has a stable UUID | `test_every_core_entity_has_a_uuid_primary_key` — all 12 core tables + `audit_events`, PK `id`, type UUID; identity generated by the domain, never the DB |
| State transitions explicit and tested | `test_states.py` — for all 7 machines, **every** (source, target) pair is asserted legal-or-rejected; no self-transitions; every state reachable; a machine that omits a state fails at import |
| Illegal transition rejected | `IllegalTransition` (409 `illegal_transition` over HTTP); e.g. `REJECTED` model can never become `CANDIDATE`/`CHAMPION`, `PENDING` run can't jump to `RUNNING`, `PENDING` deployment can't jump to `READY` |
| API → domain → persistence separation | `test_layer_import_rules` — AST check of every import in `domain/`, `application/`, `api/` against per-layer deny lists (domain may not import application/api/persistence/adapters; api may not import persistence/adapters) |
| Domain imports no MLflow/Argo/Kubernetes | same test; domain and application also may not import SQLAlchemy, FastAPI or pydantic |
| Adapter interfaces testable with fakes | `test_providers_fakes.py` — fakes satisfy all five `runtime_checkable` ports; contract behaviour asserted (idempotent submit, no cancel of a terminal run, traffic must sum to 100) |
| create/get/list Project | `test_api_projects.py`, run against **both** the in-memory and the real PostgreSQL unit of work |
| Duplicate request idempotent | identical `POST /projects` → `201` then `200`, same id, **one** row, **one** audit event; same name with different attributes → `409 conflict`; 4 concurrent identical requests → 1 project, 1 audit event; a lost insert race is caught by the unique constraint and replayed |
| Audit event created | `project.created` written in the same transaction as the project; a forced audit failure rolls the project back (`test_a_failed_audit_write_rolls_the_project_back`) |
| OpenAPI renders | `test_openapi.py` — `/openapi.json` validated by `openapi-spec-validator`, `/docs` 200 |
| ruff / mypy / pytest | below |

### The important gate: dependency isolation

`test_control_plane_runs_with_every_external_system_unavailable` runs a fresh
interpreter in which `mlflow`, `kubernetes`, `argo_workflows`, `hera`, `kserve`
and `boto3` are replaced by `None` (any import raises), then drives a real use
case through the HTTP API. It additionally asserts that SQLAlchemy, psycopg and
Alembic were never imported — the pure layers don't even need the database
driver. `test_only_adapters_may_touch_external_systems` fails the build if any
module outside `adapters/` imports an external-system client.

## Findings made while building

- **Package name.** `platform/` would shadow the standard library module of the
  same name; the package is `controlplane/`.
- **mypy caught a real design flaw.** `UnitOfWork` declared `projects`/`audit`
  as mutable attributes, which made every implementation fail the protocol
  (invariance). They are now read-only properties.
- **Composition root.** `api/` first held the production entrypoint, which has
  to import the SQL adapter — the layer test rejected it. The entrypoint moved
  to `controlplane/main.py`, so `api/` stays free of persistence.

## Known limits (deliberate, for later milestones)

- Only `Project` has repositories and an API. The other 11 entities have
  tables, domain classes and state machines, but no use cases yet.
- A new project stays `PENDING`: there is no reconciler until M14.
- The audit actor is the constant `anonymous`; a client-asserted actor header
  would be a forgeable audit trail, so identity waits for real authentication.
- `ml_platform_infra.egg-info/` is tracked in git (pre-existing); it was left
  untouched.
